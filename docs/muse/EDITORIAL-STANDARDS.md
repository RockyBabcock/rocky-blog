# MuseAI 文章编辑标准

## 内容定位

Rocky Blog 是长期维护的个人知识与生活内容博客。文章要有清晰的问题意识、真实的信息、连贯的论述和可复用的结论。不要把每篇文章写成搜索引擎关键词集合、产品广告或功能清单。

## 事实和来源

- 对技术版本、产品功能、价格、法规、研究结果、新闻和其他可能变化的信息，先查证官方文档或一手来源，并尽量注明核查日期。
- 事实性关键判断应附可访问的来源链接；优先官方文档、标准、论文和原始公告。
- 不虚构作者亲身经历、测试结果、命令输出、性能数据、统计图表、用户反馈、引用或发布日期。
- 没有运行过代码，不得写“实测通过”；没有实际数据，不得生成看似真实的图表。
- 对不确定信息明确说明版本、环境、范围或不确定性，不要把推测写成事实。
- 对第三方内容只做必要引用和转述，遵循版权边界，不大段复制文章、书籍或文档。

## 结构与可读性

### 技术文章 / 工程实践

通常使用以下结构，但按主题调整：

1. 背景与问题：目标、场景和约束。
2. 核心概念：必要定义和关键机制。
3. 方案与实现：步骤、代码和设计理由。
4. 验证与结果：只有真实执行和验证过的内容才能列为结果。
5. 权衡与局限：边界、风险、替代方案。
6. 总结：提炼可以迁移的结论。

### 工具 / 使用指南

通常包括：适用场景、环境与前提、安装 / 配置、基本用法、进阶场景、限制与排障、官方参考资料。版本信息必须和查证时一致。

### 随笔 / 生活内容

以自然段和真实观察为主，保留个人表达和叙事节奏。不要强行套用技术教程模板，不要虚构个人情绪、经历或第一人称故事。

### 周刊 / 系列内容

沿用既有系列的节奏、结构、编号和命名；新建系列前必须得到维护者确认。每一期的链接、标题和内容范围要明确，不制造虚假外链推荐。

## 语言和语气

- 中文主稿应自然、准确、避免机器翻译腔和空洞开场。
- 英语、日语、法语应面向目标语言读者重新组织表达，而不是机械逐句翻译。
- 技术术语前后一致；第一次出现时可给出原文、缩写或简短解释。
- 标题准确表达内容，不使用夸张承诺、标题党或没有证据的“终极”“最强”“完全解决”。
- 不在文章中写“作为 AI”“我作为模型”等生成过程说明，除非文章主题本身讨论 AI 生成。

## 版式

- 以可读性为先；使用清晰小节、适度列表和必要表格。
- Mermaid 用于结构、流程、时序；Infographic 用于确实适合视觉化的信息。不要每篇文章强制插入图表。
- 代码块必须标明语言；关键参数和输出需解释。代码必须与正文的技术版本相符。
- 图片要有明确用途，并提供准确 alt 文本；没有实际图片资源就不要添加虚假路径。
- 不堆叠提醒块、标签页、折叠块、彩色文字或装饰效果。
- 摘要 `description` 只概括本文确实覆盖的内容。

## 交付前自检

逐项确认：论点有依据、结论有边界、示例可读、版本准确、来源可访问、frontmatter 符合 schema、文件路径正确、标题层级合理、扩展语法已闭合、没有虚构资源或数据。
