# 06 — 状态管理与本地持久化

## 状态分层

状态应放在离它最近且能满足需求的层：

- 页面内一次性状态：局部 React state。
- 跨交互组件共享的状态：按现有模式使用 Nanostores。
- 用户偏好和阅读进度：按现有 store 封装保存在浏览器本地。
- 内容数据和路由元信息：构建阶段生成，不应复制到运行时全局 store。

不要把可以由 props 或静态数据推导的值重复存入 store。

## Nanostores

项目使用 Nanostores，并通过 React adapter 为 React island 提供订阅。Store 负责状态本身；数据解析、格式化与持久化应放在明确的 lib / store 边界中。

新增 store 时：
1. 确认是否已有等价 store。
2. 定义可预测的初始值。
3. 对持久化数据做 schema / 版本校验。
4. 处理浏览器环境缺失和异常 storage。
5. 增加 node:test 覆盖。

## 本地阅读历史

阅读历史保存在浏览器 localStorage，当前 key 为 `rocky-blog:reading-history:v1`，并支持跨标签页 storage 事件同步。

它是单浏览器 / 单设备记录，不提供用户账号、跨设备同步或服务器端数据恢复。文章收藏由独立的 Reading Shelf 管理，见下节。清除浏览器网站数据可能导致历史清空。

## 个人阅读书架（Reading Shelf）

收藏记录保存在 localStorage 的版本化 key `rocky-blog:saved-articles:v1` 中，当前上限为 120 条。条目仅保存文章 slug、标题、本地化 URL、locale、收藏时间和可选展示元数据，不保存文章正文或解密内容，也不会发送至外部服务器。

同一浏览器的其他标签页通过 storage event 更新书架状态。待读 / 阅读中 / 已完成状态由已有阅读历史的 progress 推导，不重复维护另一套阅读进度数据。书架页面提供状态过滤、搜索、排序和网格 / 列表视图。

## 阅读设置

阅读偏好保存在浏览器本地。现有能力包括：

- 内置四种字体预设（不是任意字体文件选择器）。
- 字号与行高。
- 正文版心宽度与对齐方式。
- 阅读进度显示。
- 动效等级与波浪等偏好。

调整存储结构时必须考虑旧值缺失、无效值和版本迁移，避免读取 localStorage 时阻断首屏。

## 系列阅读进度

系列阅读进度用于提供继续阅读体验。它属于本地浏览器状态，不应被描述为跨设备同步，也不要将其扩展为云端书架。

## 生命周期与多标签页

所有 window / storage 事件监听都应有对应 cleanup。不要在每次 Astro 页面切换时重复添加监听。对 localStorage 的 JSON 解析应捕获异常并恢复合理默认值。

## 隐私边界

当前产品不接入 analytics，不发送个人阅读行为到第三方统计平台。新增遥测或网络同步前必须先更新产品范围并得到明确批准。
