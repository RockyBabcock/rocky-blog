# 08 — 动效系统

## 设计目标

动效用于解释空间关系、反馈操作和建立页面节奏，不是持续吸引注意力的背景噪声。整体应细腻、有方向、有层次，并以阅读清晰度为优先。

## 动效强度

`config/site.yaml` 的 `motion` 区域控制默认动效偏好。当前等级：

| 等级 | 定位 |
| --- | --- |
| `lively` | 更完整的页面入场、滚动显现、共享元素过渡与樱花装饰 |
| `subtle` | 保留必要入场和转场，减少正文滚动显现及樱花装饰 |
| `reduced` | 关闭装饰性动效，只保留必要交互反馈 |

系统启用 `prefers-reduced-motion` 时，必须按 reduced 处理。不得只在 CSS 层关闭部分动画，却让 JS 动画、自动滚动或花瓣循环继续运行。

## 樱花效果

当前配置提供：
- `heroPetals`：首页头图的花瓣飘落效果。
- `clickBurst`：用户点击交互元素时的花瓣迸发。

花瓣应是品牌装饰，不遮挡文字、不干扰点击，不应在所有页面无限制增加粒子。需要考虑低性能设备、移动端、电量和 reduced-motion。

## 动效实现约定

- 优先动画 transform / opacity，避免频繁触发布局和绘制。
- 控制同时运行的动画实例数量。
- 需要清理 raf、timeout、observer 和事件监听。
- 页面切换后避免旧页面动画继续运行。
- 动效状态不要与主题状态耦合。
- 不能只靠颜色或运动传递关键状态。

## 验证

检查浅色 / 深色、桌面 / 移动端、键盘触发和 reduced-motion。涉及动效核心逻辑时运行 `pnpm test:motion`；涉及真实浏览器行为时运行 `pnpm test:motion:browser`（需有相应 Playwright 浏览器）。

## 非目标

不加入圣诞节特效或随机季节皮肤，不用持续粒子背景填满页面，也不为了展示动画而牺牲可读性与性能。
