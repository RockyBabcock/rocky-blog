# 05 — UI 与页面模块

## 页面构成

当前界面由全局壳层、页面模板和具体内容模块组合而成。优化时优先调整排版、视觉层次和交互一致性，不要为追求“简化”而删减既有模块。

### 首页

首页的主要内容区包括：

- **Featured Showcase：** 代表性内容或重点入口。
- **Latest Writing：** 最近发布的文章。
- **Series & Weekly：** 周刊与系列文章入口及进度信息。
- **Explore Topics：** 分类 / 主题探索。
- **Editorial Timeline：** 文章时间线。
- **个人介绍与工具栏：** 侧栏个人信息、导航，以及桌面端右侧工具区。

模块在不同断点下可以改变布局，但功能入口应保留且可访问。

### 文章页

文章页围绕标题与元信息、正文、目录、阅读进度、文章操作、专注模式和图片查看体验组织。移动端需要提供适合窄屏的标题层级、目录入口和工具操作。

### 索引与系列页

分类、标签、归档、分页和系列页面使用一致的排版与元信息语言。系列页可展示阅读进度，但进度来源是浏览器本地状态。

## 全局交互

- 主题切换和阅读偏好设置。
- Pagefind 静态搜索。
- Command Palette。
- Recent Reading / Continue Reading。
- Reading Shelf：文章收藏、状态筛选、搜索、排序，以及网格 / 列表视图。
- 分类和归档文章列表的集合内搜索 / 排序工具栏。
- Reading History 与 Series Progress。
- 目录定位、阅读进度和 Focus Mode。
- 页面过渡、悬停反馈与受控的樱花装饰。

以上是现有产品能力的说明，不代表每个模块都必须在所有视口同时显示。

## 视觉设计原则

- 先建立主次关系，再添加装饰细节。
- 使用标题、眉题、编号、时间、分类标签、细线、缩进、背景层次和留白塑造编辑式节奏。
- 樱花、叶片与星象图形应成为细节层，不要遮挡正文或抢夺标题焦点。
- 卡片不应成为所有内容的唯一呈现方式；列表、时间轴、分栏、横向轨道和版面错位都可使用。
- 悬停、焦点和按下状态要有清楚反馈，并保持键盘可用。
- 动效需控制距离、时长和频率，支持 reduced-motion。

## 开发约定

复用已有组件及设计 tokens。不要用新的局部颜色、字体体系或一组重复的 card wrapper 代替整体设计系统。组件 props 保持明确，视觉状态与数据状态分离。

## 产品边界

不新增评论、友链、播放列表、CMS、统计分析、随机推荐或外链 OG 卡片等已列为非目标的模块。新增功能需先更新 [产品范围](../PRODUCT-SCOPE.md) 并取得维护者决策。
