# 07 — 主题系统

## 目标

主题系统为阅读界面提供一致的浅色与深色外观，并确保页面、组件、Markdown、弹层和图表在切换时保持协调。

## 设计方向

视觉基调为 Premium Editorial × Contemporary Magazine × Sakura Botanical × Celestial Details。当前调色方向包含：

- 暖亚麻色背景（例如 `#F6F4F0`）。
- 柔和玫瑰色强调（例如 `#AC495F`）。
- 暮色蓝灰辅助色（例如 `#556E86`）。
- 深炭色文字 / 暗色表面（例如 `#17181D`）。

这些是方向性 token 参考，不代表所有组件应直接硬编码这些值。具体变量以主题 CSS 和设计 tokens 为准。

## Token 使用

优先使用全局 CSS custom properties 与 Tailwind 主题变量。不要在组件内复制一套近似颜色，也不要仅为一个组件创造不可复用的主题变量。

至少要区分：
- 页面背景与分层表面。
- 主文本、辅助文本和弱化文字。
- 主强调色与状态色。
- 边线、分隔和焦点 ring。
- 阴影与叠层。
- Markdown / code / diagram 的专属表面。

## 浅色与深色

主题切换应覆盖全局布局、导航、按钮、输入、弹层、文章正文、代码块、Mermaid、灯箱和设置面板。

避免只在浅色主题下验证新增样式。检查弱化文本、细线和花瓣装饰在两个主题中的对比度。

## 首屏主题初始化

主题启动逻辑应避免首屏先闪现错误主题。新增主题状态时要检查启动脚本、持久化偏好和系统主题之间的优先级，不能在组件挂载后才纠正整个页面。

## 过渡

主题变化可以使用现有主题过渡机制，但应避免全页面昂贵的持续 transition。对用户明确触发的主题切换使用适量反馈；系统 reduced-motion 时降低或关闭装饰性过渡。

## Reader preferences 与 theme 的区分

主题（light / dark）不等于阅读排版设置。字号、行高、版心、对齐和字体预设属于 reader settings。保持两套设置独立，避免设置面板出现概念混乱。
