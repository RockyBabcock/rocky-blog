# 09 — 样式系统

## 技术基础

样式系统使用 Tailwind CSS 4、Vite 插件和项目自己的 CSS layers / design tokens。Tailwind 适合表达布局与局部状态；主题色、字体、全局排版和跨模块视觉规则应由共享 tokens 管理。

## 样式入口

主要入口为 `src/styles/index.css`。该文件导入全局、主题、动效、Markdown 和页面 / 组件相关样式。修改样式前先检查 import 顺序和现有模块，避免在多个文件重复定义相同规则。

当前样式职责大致分为：

- reset 与 global：基础元素、全局排版与通用 utilities。
- theme：主题变量、浅 / 深色和主题过渡。
- motion：动效等级与动画 primitives。
- markdown：正文排版、代码、公式、图表和加密块。
- components / pages：导航、侧栏、首页、文章页、系列页、目录等。
- editorial / focus：编辑式布局与专注阅读体验。

具体文件以 `src/styles/` 实际目录和入口 import 为准。

## Design tokens

新样式优先使用已有 CSS custom properties、Tailwind utilities 和主题变量。不要在组件里硬编码独立配色、阴影、圆角或字体系统。

视觉基调：
- 编辑式标题和正文层级。
- 有节奏的留白和稳定的阅读版心。
- 细分隔线、编号、眉题和微型标签。
- 樱花、植物与星象的克制装饰。
- 清晰的悬停、焦点、按下和禁用状态。

避免所有内容统一套用卡片、厚重阴影、玻璃拟态和无意义渐变。

## 响应式

从窄屏开始验证内容流，再检查平板和宽屏。不同断点可以调整模块顺序、列数、侧栏和工具栏行为，但要保留功能入口。

避免：
- 固定宽度导致窄屏横向滚动。
- 图片没有宽高比例造成 CLS。
- hover-only 交互。
- 只适用于鼠标的复杂拖动。
- 小于合理触控尺寸的按钮。

## 性能与可维护性

- 尽量动画 transform / opacity。
- 控制模糊、backdrop-filter 和大面积阴影。
- 为图片提供合理尺寸、格式、懒加载与占位。
- 避免高特异性选择器和无边界全局覆盖。
- 重用现有 tokens，不创建只被单组件使用的重复主题系统。

## 验证

至少检查桌面与移动端、浅色与深色、键盘焦点和 reduced-motion。样式改动应确认没有影响 Markdown 正文、代码块、目录和弹层的层叠关系。
