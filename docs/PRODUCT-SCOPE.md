# Rocky Blog — 产品范围与设计原则

> 本文档定义产品层面的事实来源。README、使用指南、界面文案与 AI Agent 指令不得与本文档冲突。

## 1. 产品定位

Rocky Blog 是一个以内容创作、阅读和发现为中心的个人静态博客。核心价值是：清晰呈现文章与系列内容，提供高质量阅读体验，并让维护者可以通过 Markdown 和配置文件管理内容，而不需要维护数据库、账号系统或应用服务器。

技术基线以仓库当前代码为准：Astro 7、React 19、TypeScript、Tailwind CSS 4、静态输出、Pagefind、Nanostores 与 Motion。

## 2. 视觉与交互方向

设计关键词：

**Premium Editorial × Contemporary Magazine × Sakura Botanical × Celestial Details**

- 以编辑式排版、明确的层级、充足留白和有节奏的内容布局为基础。
- 樱花、花瓣、枝叶、星点、轨道和天象可以作为装饰语言，但必须服务于信息层次。
- 整体应成熟、克制、细腻、有艺术指导感，而不是将装饰元素堆叠成视觉噪声。
- 避免动漫 / 漫画主视觉、萌系 / kawaii、Q 版人物、幼态插画、廉价霓虹和无目的的玻璃拟态。
- 主题颜色以现有 design tokens 为准。当前方向包括暖亚麻底色、柔和玫瑰色、暮色蓝灰与深炭色；不要在局部组件中任意另造一套调色板。
- 增加细节时优先使用边线、标记、编号、微型图形、细腻纹理、分隔、悬停反馈与有节制的动效，而不是无差别地增加卡片和阴影。

### 设计验收要求

维护者明确要求界面不能显得空荡、单薄或缺乏表现力。后续 UI 优化应主动提升视觉层次、版面节奏和细节丰富度，而不是只做结构简化。

- 各主要模块应具有可辨认的视觉组织方式；允许采用不对称网格、分栏、时间线、横向轨道、索引列表、特色封面和层叠表面等不同版式。
- 允许并鼓励使用有设计目的的微细节：眉题、编号、微标签、细分隔线、边框、角标、几何线条、轻纹理、植物枝叶、樱花花瓣、星点、轨道和星座式图形。
- 不允许通过删除模块、隐藏入口、缩减信息量或随意拉大空白来“优化”页面；也不允许无目的堆叠卡片、阴影、渐变、粒子和装饰。
- 优化目标是在保持阅读清晰度的前提下，让页面更完整、更有识别度、更有吸引力；功能组件必须可用，装饰元素不得抢夺内容焦点。
- 视觉验收需要覆盖桌面和移动端、浅色和深色主题、键盘交互，以及 `prefers-reduced-motion` 场景。

## 3. 保留的页面与功能

### 主要内容页面

- 首页：Featured Showcase、Latest Writing、Series & Weekly、Explore Topics、Editorial Timeline，以及个人介绍 / 侧栏与桌面端工具栏。
- 文章详情页、分类页、标签页、归档页、分页、周刊 / 系列页面与 About 页面。
- 首页模块可重排和扩展，但不能为了简化而删除既有内容模块或减少其信息量；任何结构性调整都要确认原功能仍可访问。

### 阅读与发现

- Pagefind 静态全文搜索。
- 命令面板、站内导航、最近阅读 / 继续阅读入口。
- 本地阅读历史与系列阅读进度。
- 个人 Reading Shelf：保存文章，按待读 / 阅读中 / 已完成筛选，并提供搜索、排序和网格 / 列表视图；阅读状态复用现有阅读历史。
- 分类和归档文章集合内搜索 / 排序工具栏。
- 深色 / 浅色主题和阅读设置：内置四套字体预设、字号、行高、版心、对齐、滚动进度、波浪和动效等级。
- 阅读目录、阅读进度、专注模式、响应式图片、图片灯箱 / 缩放与 LQIP 占位。
- 页面过渡、滚动显现、卡片和按钮反馈、樱花花瓣等现有动效；所有动效需遵循 reduced-motion。

### 内容与 Markdown

- GFM、Shiki、KaTeX、Mermaid、Infographic。
- Shoka 风格容器、标签页、折叠、文字效果、隐藏文字与 Ruby 注音。
- 代码块复制、全屏和折叠等现有增强。
- 文章可设置分类、标签、封面、摘要、置顶、草稿、目录编号、数学公式和翻译关联。
- 整篇文章与局部内容块的 AES-256-GCM 静态加密。

### 工程与发布

- 静态构建与静态托管。
- 多语言界面：中文（默认）、英语、日语、法语。
- canonical、Open Graph、hreflang、sitemap、robots 与 Pagefind 索引。
- 通过 YAML 和 Markdown 配置，不引入运行时数据库。

### 3.1 内容生产与发布流程

Markdown 是主要内容交付形式。维护者可以使用 MuseAI 或其他写作工具辅助生成文章，再将校验后的 `.md` 文件加入 `src/content/blog/`。文章必须符合 `src/content.config.ts` 的 frontmatter schema、目录结构、分类映射、稳定 slug 和翻译关联规则。

内容生产工具不属于网站运行时架构：MuseAI 不是 Rocky Blog 的 CMS、后端 API 或在线写作室。默认发布流程为：

1. 通过 MuseAI 或其他编辑工具生成 / 编辑 Markdown。
2. 校验必填 frontmatter、日期、分类、标签、封面路径、链接和文件位置。
3. 如有译文，按相同相对路径放入 `en/`、`ja/`、`fr/`，并核对 `link` / `translationKey`。
4. 运行适用的内容检查和静态构建。
5. 将仓库中的 Markdown 与代码一起提交，并部署生成的静态产物。

不要为了适配单篇文章或生成工具而使用 schema 不支持的字段；不要伪造代码运行结果、数据、来源或翻译完成状态。

## 4. 语言策略

支持语言固定为：

| 代码 | 语言 | 路由 |
| --- | --- | --- |
| `zh` | 中文（默认） | 无语言前缀 |
| `en` | English | `/en/` |
| `ja` | 日本語 | `/ja/` |
| `fr` | Français | `/fr/` |

不要增加韩语。新增语言必须先更新产品决策、UI 字典、路由、SEO、翻译配置和测试，不能只增加一个标签。

界面字典覆盖四种语言；文章翻译按实际文件提供情况生成。没有译文时，系统可以回退展示默认语言内容，不得宣称每篇文章都已完整翻译。

## 5. 已确认移除的功能与当前非目标

以下项目已有明确的移除 / 不再建设决定。除非维护者今后明确改变决定，否则不得以重命名、轻量版或替代组件的形式重新引入：

1. 友链 / 朋友链接系统。
2. 写作室、浏览器内编辑器、CMS 管理后台和文章管理控制台。
3. 全站播放列表、站点背景音乐播放器及其相关功能。
4. Bangumi / 追番管理。
5. Moments / 碎碎念。
6. 评论系统。
7. Umami 或其他访问统计、用户行为分析集成。
8. AI 文章摘要生成与 AI 自动总结。
9. 基于 embedding / 向量索引的语义相似文章推荐。

RSS 在第 6 节单独记录：已从当前产品与代码中移除。

### 当前不纳入产品基线的能力

以下能力不是当前产品承诺，也没有获批的新建计划。Agent 不应自行实现；若需求再次出现，应先向维护者确认，而不是把“当前没有”解释成“维护者已永久否决”：

- 随机文章推荐、外链 Open Graph 预览卡片、Tweet / X 和 CodePen 嵌入。
- 本地字体文件扫描 / 上传 / 任意选择器；当前阅读设置只保留内置字体预设。
- Colophon / 单篇文章制作人员元数据系统。
- LRC 歌词、文章媒体播放列表及自定义音频 / 视频播放器。
- 用户账号、云数据库、服务端阅读历史同步、跨设备云书架 / 收藏同步。Reading Shelf 是浏览器本地书架。

## 7. 数据与安全边界

### 阅读历史和设置

- 阅读历史、偏好设置、系列进度与收藏文章保存在浏览器本地存储。Reading Shelf 使用版本化 key `rocky-blog:saved-articles:v1`，当前最多保留 120 条；同一浏览器的标签页之间可通过 storage event 同步。
- 收藏数据仅保存文章元信息，不保存正文或解密后的内容，也不会发送到外部服务器。
- 不存在账号登录、跨设备云同步、服务端数据库或云端书架。
- 清理浏览器站点数据可能导致本地记录丢失。

### 静态加密

- 当前实现使用 AES-256-GCM，并在构建阶段生成加密内容。
- 密文与用于派生密钥的公开参数会随静态页面交付；任何人都可以下载密文并离线尝试密码。
- 密码强度、密钥派生成本和读者侧解密共同决定实际保护能力。
- 这不是 DRM、服务端鉴权或真正的私有内容存储。不要在文档中承诺“密码不会进入任何公开产物”或“无法绕过”。
